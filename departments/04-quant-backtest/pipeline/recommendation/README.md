# 종목 추천 파이프라인 (트레이딩 보조형)

유니버스 전 종목을 채점해 **종목 + 지지·저항·목표가·손절가**를 근거와 함께 낸다.
자산배분형 포트폴리오(`orchestration/workflows/portfolio_recommendation.py`)와는
다른 산출물이다 — 저쪽은 적합성·게이트를 소유하고, 여기는 *어느 종목을 왜* 를 만든다.

## 왜 3단인가 — 외부 조회 예산이 층을 강제한다

LS 조회는 **초당 1건 · 하루 2,000회**(`MCP_LS_DAILY_CAP`). 종목당 3회(수급·공매도·
밸류)면 전 종목 2,694 × 3 = 8,082회로 캡을 넘고 45분 넘게 걸린다. 그래서 값싼
축으로 먼저 좁히고, 비싼 축을 좁힌 후보에만 붙인다.

| 단계 | 대상 | 데이터 | 실행 위치 | 실측 비용 |
|---|---|---|---|---|
| 1층 `screen_universe` | 2,694 → 1,047 채점 → 후보 25 | `market.market_bars` 일봉 | 호스트(.venv) | 외부호출 0, 3.3초 |
| 1.5층 `enrich_candidates` | 후보 25 → N | LS 수급·공매도·밸류 | `hedgefund-ls-mcp` | 3N회, 3N초 |
| 2층 `judge_candidates` | N | 네이버 뉴스 · DART 공시 · vLLM | `hedgefund-research-mcp` | 종목당 2회 + LLM 2회 |

컨테이너가 갈리는 것은 자격이 갈리기 때문이다 — LS 키는 `ls-mcp` 에만,
네이버/DART/워커모델은 `research-mcp` 에만 있다. 단계 사이는 JSON 파일로 넘긴다.

## 파일

- `instrument_scoring.py` — **순수 코어.** 축 정의·합성·가격계획(지지/저항/목표/손절).
  I/O 없음. `python instrument_scoring.py` 로 자체점검.
- `narrative_axes.py` — 뉴스·공시 호재/악재 축. LLM 은 여기서만 쓴다.
  `python narrative_axes.py` 로 자체점검(네트워크 없음, 가짜 LLM).
- `screen_universe.py` / `enrich_candidates.py` / `judge_candidates.py` — 단계별 실행기.
- `run_pipeline.sh` — 3단을 순서대로 돌린다.

## 설계 규칙

**LLM 은 관련성 판단과 서술만 한다** (CLAUDE.md). 목표가·손절가·비중은 전부
`instrument_scoring.py` 의 결정론 계산이다. LLM 이 숫자를 내면 근거를 검증할 수 없다.

**기권은 0점이 아니다.** 축이 죽으면 `ABSTAINED`/`NO_SOURCE` 로 표시하고 가중합의
**분자와 분모 둘 다에서** 뺀다. 남은 유효 가중치가 50% 아래면 종합점수를 내지 않고
`INSUFFICIENT` 로 떨어진다. 0으로 채우면 "데이터 없음"과 "보고 중립이라 판단함"이
같은 점수가 된다.

분모는 **가중치표 전체**다. 전달된 축만 분모로 쓰면 축을 빼먹은 호출부가 조용히
만점을 받는다 — 기권을 0으로 채우는 실패를 뒷문으로 다시 들이는 셈이다.

**점수가 높아도 가격 자리가 나쁘면 뺀다.** 손익비 1.5 미만이거나 손절폭이 진입가
대비 12%를 넘으면 후보에서 제외하고 이유를 `skipped_before_quota` 에 남긴다.

## ⚠ 검증 결과 — 1층 랭킹은 현재 **역방향**이다 (2026-08-24)

`backtest_momentum.py` 를 사전등록 규약으로 개발 구간(2016-07~2022-12,
리밸런스 80회)에 돌린 결과. 홀드아웃(2023~)은 열지 않았다.

| | 결과 | 사전등록 판정 |
|---|---|---|
| Q1 모멘텀 십분위 | D10−D1 = **−1.82%p**, t = **−5.96** (+20d) | **불합격 (역방향)** |
| Q2 가격계획 손익 | 평균 +0.04%, t=+0.29, 승률 35.2% | **불합격** |
| Q3 목표 배수 | 신고가권 MFE 중앙값 2.55 ATR | 3.2 → 2.55 재보정 |
| IC 지도 90셀 | **전부 음수**, 43셀 |t|>=3.5 · 대형주에서 최강 | 반전이 구조적 |
| 반전 홀드아웃 | IC −0.080 (t=−3.94), 개발 −0.082와 거의 동일 | **재현됨** |
| 반전 **손익** | 초과 +0.07%, t=+0.12, 낙폭 −59.3% | **불합격** |

상위 모멘텀 십분위가 하위보다 20일 후 **1.82%p 낮다.** 20/60일 형성 + 20일
보유는 학술 모멘텀 구간(12-1개월)이 아니라 **단기 반전 구간**이다.

Q2 의 원인은 Q3 가 설명한다 — 같은 표본의 최대**불리**이동 중앙값이 2.52 ATR
인데 손절이 `MAX_RISK_ATR = 2.0` 이라 절반 이상이 손절에 먼저 닿는다
(손절 선도달 62.1% vs 목표 선도달 31.0%).

**부호를 뒤집지 않았다.** 그건 수정이 아니라 새 가설이고, 별도 사전등록이
필요하다. 또 유니버스에 폐지가 0건이라 생존편향이 정확히 이 결과가 나오는
방향(패자 회복)으로 작용한다 - 반전의 **크기**는 과장돼 있다.

**IC 는 재현됐지만 손익으로 전이되지 않았다.** 대형주 60일 반전은 개발·홀드아웃
양쪽에서 IC −0.08 로 확인됐는데(→ `ic_surface.py`, `ic_stability.py`), 그 신호로
상위 20종목 롱온리를 짜면 벤치마크 대비 초과수익이 +0.07%(t=+0.12)에 그치고
최대낙폭이 −59.3% 다. **순위 상관이 있다는 것과 돈이 된다는 것은 다른 문제다.**

**따라서 현재 이 파이프라인의 종목 순위를 매매에 쓰면 안 된다.**

## 답변 층 — 근거 등급제

`answer_builder.py` 가 카드를 사용자 답변으로 바꾸며 **모든 문장에 등급**을 붙인다.

| 등급 | 뜻 | 현재 해당 |
|---|---|---|
| 측정됨 | 예측력이 백테스트로 측정 | 위험 고지(도달률·초과수익 부재)뿐 |
| 관측됨 | 데이터에서 직접 읽음 | 종가·수급·공매도·스윙 접점 |
| 산출됨 | 명시된 규칙으로 계산 | ATR·목표가·손절가 |
| 판단 | LLM 서술 | 뉴스·공시 호재/악재 |
| 미검증 | 계산되나 예측력 미측정 | **종합점수·축 가중치** |

설계 근거는 2026 연구의 지적("LLM 은 데이터가 낡아도 같은 확신으로 답한다 →
답변 조각마다 신뢰도 지표")과 CFA Standard V(B)("투자 프로세스의 중대한
리스크와 **한계**를 공개")다. 자본시장법 설명의무·위험고지·적합성에 맞춰
위험·기간·무효화 조건·적합성 판정을 별도 절로 낸다.

**예측력이 측정된 긍정 근거가 없으면 산출물은 `정보제공` 이지 `투자권유` 가
아니다.** 현재 전 종목이 `정보제공` 으로 분류된다. 투자성향 프로필이 없으면
적합성은 통과가 아니라 `UNKNOWN` 이다.

## 두 갈래 산출물

이 폴더에는 파이프라인이 **둘** 있다. 무엇이 종목을 고르는가가 다르다.

| | `run_pipeline.sh` | `run_ownership.sh` |
|---|---|---|
| 고르는 주체 | 차트(모멘텀 랭킹) | **지분공시 매집** |
| 근거의 성격 | 예측 | **관측** |
| 검증 상태 | 초과수익 없음(t=+0.12) | 관측이라 예측 검증 대상이 아님 |
| 종합점수 | `[미검증]` 로 표시 | **아예 내지 않음** |

**왜 둘째를 만들었나.** 백테스트가 두 번 다 엣지를 못 찾았다(모멘텀 초과
+0.07%/t=0.12, 반전은 IC 재현되나 손익 0). 검증 못 한 예측을 추천으로 파는 대신
**관측된 사실을 보고**한다 — "다산인베스트가 2주간 지분 7.11%p 장내매수"는
공시에 적힌 사실이고 접수번호로 확인된다.

### `run_ownership.sh` — 관측 기반 추천

    ./run_ownership.sh [후보수] [조회일수]     # 기본 4, 14일

| 단 | 하는 일 | 실행 위치 | 실측 |
|---|---|---|---|
| 1 `scan_ownership` | DART 지분공시 시장 전체 → 매집 종목 | research-mcp | 공시 1,079건 → 상장사 509곳 **전수** → 34종목, 83초, DART 345회. 6시간 캐시 |
| 2 `enrich_ownership` | 수급(t1717)·테마(t1532)·밸류(t3320)·가격계획 | ls-mcp | 종목당 LS 3회. 초당 1건이 계약이라 병렬화하지 않는다 |
| 3 `judge_candidates` | 뉴스·공시 호재/악재 (vLLM) | research-mcp | 종목당 LLM **1회**(뉴스+공시 합침). 4종목 37초 |
| 4 `render_answers` | 근거 등급 답변 | 호스트 | 즉시 |

**증가를 다 매집으로 세지 않는다.** `ownership_flow.classify_reason` 이 사유를
MARKET_BUY / STRUCTURAL / DISPOSAL / UNCLASSIFIED 로 나누고 **장내 순증만**
순위에 쓴다. 실측에서 "전환사채권 인수 +38.51%p" 가 나왔는데 그건 시장에서 산
게 아니다. `elestock`(임원·주요주주)은 사유 필드가 없어 UNCLASSIFIED 로 남고
순위에 안 들어간다 — 맥락으로만 싣는다.

**API 함정 2개** (둘 다 조용히 틀린 답을 만든다):
- `rcept_dt` 형식이 목록(`20260825`)과 상세(`2026-08-25`)가 다르다. 문자열로
  비교하면 기간 필터가 전부 거짓이 되어 **파싱 0건**이 된다.
- `majorstock` 과 `elestock` 은 **필드 이름이 완전히 다르다**
  (`stkrt_irds` vs `sp_stock_lmp_irds_rate`). 하나로 읽으면 한쪽이 전부 None 이
  되어 "? (보유 None%)" 로 나간다.

**반드시 같이 나가는 한계**: 지분공시는 후행 지표다(5% 룰은 5영업일 내 보고).
그리고 "기관·내부자가 샀다"가 "오른다"는 뜻이 아니며 **그 관계는 측정하지 않았다** —
답변에 `[미검증]` 으로 명시된다.

## 운영 주의 (2026-08-25 실측)

**컨테이너를 띄울 때 오버레이 세 개가 다 필요하다.**

    -f docker-compose.yml \
    -f deploy/aws/docker-compose.paper-order.yml \
    -f docker-compose.model.yml

`paper-order.yml` 이 `DATABASE_URL` 을 로컬 control DB(`hgfinance_runtime`
최소권한 롤)로 돌린다. **빼면 루트 `.env` 의 빈 Supabase 를 본다** — 그쪽은
`reference`/`execution`/`quant`/`research` 전부 0행이라 심볼 조회부터 죽는다.
`model.yml` 은 워커 모델 좌표인데 `paper-order.yml` 에도 같은 키가 있어
충돌하지 않는다. 둘 중 하나만 고르는 실수가 실제로 두 서비스에서 났다.

떠 있는 조합 확인:

    docker inspect <container> \
      --format '{{index .Config.Labels "com.docker.compose.project.config_files"}}'

**DART 기업색인**은 첫 조회에 231초가 걸린다. 외부 응답 비영속 계약 때문에
프로세스 메모리에서만 재사용하므로 같은 프로세스의 두 번째 조회부터 빠르다.
컨테이너를 새로 만들면 다시 한 번 조회한다 — 그 실행만 느리다.

## 실행

    ./run_pipeline.sh [후보수]     # 기본 6

단계 사이는 `/tmp/recommendation/*.json` 으로 넘어가므로 중간에 끊겨도 그
파일부터 다시 시작할 수 있다. 실측 완주 시간: 1층 3.7초 + 1.5층 약 3N초 +
2층 종목당 LLM 2회 + 3층 즉시.

## 알려진 한계

- **1층 랭킹이 역방향으로 측정됐다** (위 참조). 축 구조·비용·게이트는 재사용
  가능하지만 순위 자체는 아직 못 쓴다.
- **story dedup 이 불완전하다.** 제목 토큰 겹침으로는 문구가 다른 동일 사건을
  못 접는다(실측: 엔비디아 협력 기사 3건이 남았다). 임베딩 군집이 필요.
- ~~DART 첫 조회가 222초~~ → 24시간 디스크 캐시로 231초→0초 (2026-08-25 고침).
- **수급 이력이 없다.** LS 는 현재 시점 조회만 준다. 축 계수를 검증하려면
  일별 수집기가 있어야 한다.
- ~~`_shcode_of` 가 문자 섞인 코드에서 멈춘다~~ → `isalnum()` 판정으로 고침
  (2026-08-25). 1층은 여전히 보통주만 쓴다 — 조회가 막혀서가 아니라
  우선주를 추천 대상으로 삼는 게 부적절해서다.
