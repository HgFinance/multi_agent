# 종목 추천 파이프라인 (트레이딩 보조형)

유니버스 전 종목을 채점해 **종목 + 지지·저항·목표가·손절가**를 근거와 함께 낸다.
자산배분형 포트폴리오(`orchestration/workflows/portfolio_recommendation.py`)와는
다른 산출물이다 — 저쪽은 적합성·게이트를 소유하고, 여기는 *어느 종목을 왜* 를 만든다.

## 왜 3단인가 — 외부 조회 예산이 층을 강제한다

LS 조회는 **초당 1건 · 하루 2,000회**(`MCP_LS_DAILY_CAP`). 종목당 3회(수급·공매도·
밸류)면 전 종목 2,694 × 3 = 8,082회로 캡을 넘고 45분 넘게 걸린다. 그래서 값싼
축으로 먼저 좁히고, 비싼 축을 좁힌 후보에만 붙인다.

| 단계 | 대상 | 데이터 | 실행 위치 | 실측 비용 |
|---|---|---|---|---|
| 1층 `screen_universe` | 2,694 → 1,047 채점 → 후보 25 | `market.market_bars` 일봉 | 호스트(.venv) | 외부호출 0, 3.3초 |
| 1.5층 `enrich_candidates` | 후보 25 → N | LS 수급·공매도·밸류 | `hedgefund-ls-mcp` | 3N회, 3N초 |
| 2층 `judge_candidates` | N | 네이버 뉴스 · DART 공시 · vLLM | `hedgefund-research-mcp` | 종목당 2회 + LLM 2회 |

컨테이너가 갈리는 것은 자격이 갈리기 때문이다 — LS 키는 `ls-mcp` 에만,
네이버/DART/워커모델은 `research-mcp` 에만 있다. 단계 사이는 JSON 파일로 넘긴다.

## 파일

- `instrument_scoring.py` — **순수 코어.** 축 정의·합성·가격계획(지지/저항/목표/손절).
  I/O 없음. `python instrument_scoring.py` 로 자체점검.
- `narrative_axes.py` — 뉴스·공시 호재/악재 축. LLM 은 여기서만 쓴다.
  `python narrative_axes.py` 로 자체점검(네트워크 없음, 가짜 LLM).
- `screen_universe.py` / `enrich_candidates.py` / `judge_candidates.py` — 단계별 실행기.
- `run_pipeline.sh` — 3단을 순서대로 돌린다.

## 설계 규칙

**LLM 은 관련성 판단과 서술만 한다** (CLAUDE.md). 목표가·손절가·비중은 전부
`instrument_scoring.py` 의 결정론 계산이다. LLM 이 숫자를 내면 근거를 검증할 수 없다.

**기권은 0점이 아니다.** 축이 죽으면 `ABSTAINED`/`NO_SOURCE` 로 표시하고 가중합의
**분자와 분모 둘 다에서** 뺀다. 남은 유효 가중치가 50% 아래면 종합점수를 내지 않고
`INSUFFICIENT` 로 떨어진다. 0으로 채우면 "데이터 없음"과 "보고 중립이라 판단함"이
같은 점수가 된다.

분모는 **가중치표 전체**다. 전달된 축만 분모로 쓰면 축을 빼먹은 호출부가 조용히
만점을 받는다 — 기권을 0으로 채우는 실패를 뒷문으로 다시 들이는 셈이다.

**점수가 높아도 가격 자리가 나쁘면 뺀다.** 손익비 1.5 미만이거나 손절폭이 진입가
대비 12%를 넘으면 후보에서 제외하고 이유를 `skipped_before_quota` 에 남긴다.

## ⚠ 검증 결과 — 1층 랭킹은 현재 **역방향**이다 (2026-08-24)

`backtest_momentum.py` 를 사전등록 규약으로 개발 구간(2016-07~2022-12,
리밸런스 80회)에 돌린 결과. 홀드아웃(2023~)은 열지 않았다.

| | 결과 | 사전등록 판정 |
|---|---|---|
| Q1 모멘텀 십분위 | D10−D1 = **−1.82%p**, t = **−5.96** (+20d) | **불합격 (역방향)** |
| Q2 가격계획 손익 | 평균 +0.04%, t=+0.29, 승률 35.2% | **불합격** |
| Q3 목표 배수 | 신고가권 MFE 중앙값 2.55 ATR | 3.2 → 2.55 재보정 |

상위 모멘텀 십분위가 하위보다 20일 후 **1.82%p 낮다.** 20/60일 형성 + 20일
보유는 학술 모멘텀 구간(12-1개월)이 아니라 **단기 반전 구간**이다.

Q2 의 원인은 Q3 가 설명한다 — 같은 표본의 최대**불리**이동 중앙값이 2.52 ATR
인데 손절이 `MAX_RISK_ATR = 2.0` 이라 절반 이상이 손절에 먼저 닿는다
(손절 선도달 62.1% vs 목표 선도달 31.0%).

**부호를 뒤집지 않았다.** 그건 수정이 아니라 새 가설이고, 별도 사전등록이
필요하다. 또 유니버스에 폐지가 0건이라 생존편향이 정확히 이 결과가 나오는
방향(패자 회복)으로 작용한다 - 반전의 **크기**는 과장돼 있다.

**따라서 현재 이 파이프라인의 종목 순위를 매매에 쓰면 안 된다.**

## 알려진 한계

- **1층 랭킹이 역방향으로 측정됐다** (위 참조). 축 구조·비용·게이트는 재사용
  가능하지만 순위 자체는 아직 못 쓴다.
- **story dedup 이 불완전하다.** 제목 토큰 겹침으로는 문구가 다른 동일 사건을
  못 접는다(실측: 엔비디아 협력 기사 3건이 남았다). 임베딩 군집이 필요.
- **DART 첫 조회가 222초.** `external_sources._load_corp_index()` 가 corpCode.xml
  을 받는 비용이고 프로세스 안에서만 캐시된다. `judge_candidates` 가 미리 데운다.
- **수급 이력이 없다.** LS 는 현재 시점 조회만 준다. 축 계수를 검증하려면
  일별 수집기가 있어야 한다.
- `ls_mcp_server._shcode_of` 가 종목코드를 `\d{6}` 로만 인식해 `0015N0` 같은
  우선주 코드가 DART 이름 조회로 새고 멈춘다. 1층이 보통주만 남겨 우회한다.
