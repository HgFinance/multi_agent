# ADR-0004: 해석(Insight)을 1급 객체로 분리하고 LLM 자율성을 확대한다

- 상태: ACCEPTED
- 결정일: 2026-08-04
- 제안·소유: 재일 (리서치본부 RES / 퀀트·백테스트본부 QNT)
- 영향 문서: `HEDGE_FUND_MASTER_PLAN.md`(개발 원칙), `CLAUDE.md`(아키텍처 절)

## 배경

`CLAUDE.md`의 아키텍처 절은 이렇게 적고 있다.

> LLM은 관련성 판단과 서술 작성에만 쓴다. Point-in-Time 필터, 인용 검증,
> 한도 검사 같은 규칙 판정은 결정론적 Python이 한다.

이 문장을 구현하면서 **"서술 작성에만"을 해석까지 포함하는 것으로 읽었다.**
그 결과 분석가 6인이 전부 다음 형태가 됐다.

```
compute(결정론)   라벨을 정한다      "추세 형성" / "위험선호" / "정상"
narrate(LLM)      라벨을 문장으로     그 라벨을 설명하는 문장
verify(결정론)    수치를 대조         확정치 풀에 없으면 창작으로 격리
```

리포트에 나타난 결과:

| 분석가 | 계산 | 라벨(코드) | 서술(LLM) |
|---|---|---|---|
| RES-04 | ADX 28.3 | 추세 형성 | 그 라벨의 설명 |
| RES-07 | 폭 비율 1.42 | 위험선호 | 그 라벨의 설명 |
| RES-03 | 스프레드 0.41% | 정상 | 그 라벨의 설명 |

**셋을 가로질러 "그래서 무슨 뜻인가"를 말하는 자리가 없다.** 총괄이 thesis를
쓰지만 모든 문장이 확정치 대조를 받으므로 결국 숫자 나열로 수렴한다.

재일님 지적(2026-08-04): *"LLM이 서술만 하면 랭체인 쓰는 이유가 뭐임. 리포트
자체는 인사이트를 만들어 내야 하는 거 아님. 그래야 리서치 본부가 발전할 것 같은데"*

## 문제 정의

원칙이 나열한 결정론 대상은 전부 **규칙 판정**이다.

- Point-in-Time 필터 — 이 문서를 그때 볼 수 있었나
- 인용 검증 — 이 수치가 근거에 있나
- 한도 검사 — 한도를 넘었나

셋 다 **틀리면 컴플라이언스 사고**다. 기계가 해야 맞다.

그런데 *"이 세 신호가 같이 나타난다는 게 무슨 뜻인가"*는 규칙 판정이 아니다.
틀려도 사고가 아니라 **틀린 가설**이다. 둘을 같은 범주로 묶은 것이 오독이었다.

## 결정

**해석을 Fact와 다른 종류의 객체로 분리하고, 검증 방식도 다르게 한다.**

| | Fact | Insight |
|---|---|---|
| 무엇 | 수치·사실 | 해석·가설 |
| 생성 | 결정론 계산 | LLM 자율 |
| 검증 | 확정치 풀 대조 + `evidence_ids` | **수치 대조 안 함** |
| 대신 요구 | — | 교차 참조 2 + **반증 조건** + 판정 지평 |
| 틀렸을 때 | 창작(사고) | 틀린 가설(정상) |

### 반증 조건이 자유와 규율을 동시에 준다

LLM은 마음껏 해석하되 `falsifier`(무엇이 관측되면 이 해석이 틀리는가)를
쓰지 못하면 통과하지 못한다. **헛소리는 반증 조건을 쓸 수 없다.**

"없다", "알 수 없음", "해당 없음" 같은 회피는 정규식으로 거부한다 —
틀릴 수 없는 문장은 분석이 아니다.

### 교차 참조 2개 이상

한 Fact만 가리키면 해석이 아니라 그 Fact의 **재진술**이다. 서로 다른 분석가
2인 이상의 근거를 가로질러야 한다 — 같은 분석가의 Fact 둘은 한 관점이다.

### 그리고 채점된다

반증 조건과 지평이 있으므로 `packet_claims`로 발행되고 지평이 지나면
대조된다. **자가 발전의 대상이 지표에서 판단으로 넓어진다.**

신뢰도 `LOW/MEDIUM/HIGH`를 `0.3/0.5/0.7`로 바꾸지 않는다 — 있지도 않은
정밀도를 만들어내는 짓이고, Brier는 실제 확률을 낸 주장에만 쓴다.

## 변경되지 않는 것

**규칙 판정은 그대로 결정론이다.** PIT 필터, 인용 검증, 한도 검사, 라벨 결정,
Universe 판정, 데이터 품질 게이트 — 전부 파이썬이 한다.

부서 간 권한 분리도 그대로다. Insight는 근거이지 주문·목표비중·승인이 아니다.

## 함께 도입한 것 — 심의(deliberation) 순환

해석을 열기만 하면 검증되지 않은 자유가 된다. **되돌아가는 경로**를 같이 넣었다.

```
check_universe → check_data_quality → assemble_evidence
                                          ▲
   analyze_* (6인) ──INSUFFICIENT──▶ bump_gap_fill
        │
        ▼
   draft_packet → interpret → challenge_packet
                     ▲              │
                     └─ bump_revision ◀ 반박이 지목한 축을 해석이 안 다뤘으면
```

이전 그래프는 선형 간선 9개 + 조건부 2개였다 — 함수를 순서대로 부르는 것과
다를 게 없었고, LangGraph를 쓸 이유가 없었다. 지금은 노드 16 / 간선 19 /
조건부 분기 5이며 **순환이 둘**이다.

**순환 판정은 결정론이다.** "다시 할까?"를 LLM에게 물으면 매번 다르게 답하고
재현이 깨진다. 그리고 두 순환 모두 상한이 있다(각 1회) — 자체점검이 실제로
루프를 돌려 유한성을 확인한다. 무한 반복은 최악의 실패다.

## 대안과 기각 사유

**(A) 원칙 그대로 두고 프롬프트만 개선** — 확정치 대조가 모든 문장에 걸리는
한 숫자 나열로 수렴한다. 실제로 여러 번 시도했고 매번 같은 결과였다.

**(B) 확정치 대조를 느슨하게** — 창작 수치가 돌아온다. 이번 세션에서 창작을
4~5건에서 0건으로 줄인 것이 그 대조 덕분이다. 가드를 푸는 게 아니라 **다른
종류의 객체를 만드는 것**이 답이다.

**(C) Insight를 자유 텍스트로** — 채점이 안 된다. 채점이 안 되면 학습 고리에
못 들어가고, 그러면 "발전하는 리서치본부"가 성립하지 않는다.

## 위험과 완화

| 위험 | 완화 |
|---|---|
| LLM이 그럴듯한 헛소리를 함 | 반증 조건 강제 + 교차 참조 2 + 참조 무결성 검사 |
| 해석이 사실처럼 읽힘 | 리포트에서 절을 분리(`## 인사이트 (교차 해석)`) |
| 인사이트가 안 나오는데 이유를 모름 | 거부 사유를 보존해 리포트에 표시 |
| 순환이 안 끝남 | 상한 + 유한성 자체점검 |
| 성적 나쁜 해석이 계속 나옴 | `method_key = insight_<kind>`로 채점 → 성적 되읽기 |
