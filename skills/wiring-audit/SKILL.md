# 배관 점검 - 값이 없을 때 어디를 먼저 보는가

## 언제 쓰나

이런 말이 나오려 할 때. **말하기 전에 돌린다.**

- "지표가 부족해 근거를 못 쓰겠다"
- "값이 계속 `None` 이다" · "왜 이 수치가 안 나오지"
- "도구를 줬는데 안 쓴다" · "가드가 정상 인용을 막는다"
- "실행면이 없다" · "데이터셋이 없다"

**이 문장들은 결론이 아니라 출발점이다.** 상당수는 모델이나 프롬프트 문제가
아니라 배관 문제다 - 데이터는 이미 있는데 층 사이에서 조용히 떨어진다.
예외도 안 나고 로그도 안 남고 그냥 값이 없거나 0이 된다.

## 왜 이걸 먼저 하나 (2026-08-12 실측)

하루에 배관 결함 **열두 건**이 나왔다. 전부 데이터도 구현도 이미 있었다.

| 증상 | 실제 원인 |
|---|---|
| `'low_volatility' 전략 구현 필요` | 구현은 8종 다 있었다. 카탈로그가 손글씨 2종 |
| `실행면이 노출되지 않았다` | 실행면은 거기 있었다. 스킬이 실행을 금지 |
| `사상할 데이터셋이 없다` | 유도본이 있었다. 원시 이름만 대조 |
| `경쟁 설명 코드가 어휘 밖이다` | 어휘에 있었다. 뒤에 산문이 붙음 |
| `ModuleNotFoundError` | 설치돼 있었다. PATH 밖 |
| `Connection refused` | DB 는 살아 있었다. 호스트 주소를 컨테이너에서 씀 |

**여섯 건 다 "없다" 는 메시지였는데 여섯 건 다 있었다.** 메시지를 믿고 만들려
했으면 이미 있는 것을 여섯 번 다시 만들었을 것이다.

## 카드를 시작할 때 - 먼저 내 능력을 훑는다

```bash
sh "$(find /opt/data -name capabilities.sh | head -1)"
```

실행면·경로·마운트·원장 DSN·HTTP 창구·설치된 스킬을 한 번에 보여 준다.
**"없다" 를 적으려면 이 목록을 먼저 봐라.** 오늘 오진 세 건이 전부 이걸 안
해서 났다 - 셋 다 있는 것을 없다고 했다.

읽는 법:
- `있음` 이면 쓸 수 있다. 경로까지 같이 나온다
- `QUANT_REPO` 가 저장소 전체다. `/app` 이 아니다 - 헷갈리면 여기서 확인
- **DSN 이 없어도 시세는 HTTP 로 읽는다**(`market-api:8036`)
- **MCP 가 없어도 도구가 없는 게 아니다** - HTTP 창구가 따로 있다

## 돌리는 법

```bash
# 스크립트 위치는 프로필 구조에 따라 한 겹 더 들어가 있을 수 있다 - 찾아서 쓴다
SCAN=$(find /opt/data -path "*wiring-audit/scripts/scan_wiring.py" | head -1)

python "$SCAN" /app/repo                                  # 저장소 전체
python "$SCAN" /app/repo/departments/04-quant-backtest    # 한 부서만
python "$SCAN" /app/repo --json > /tmp/wiring.json         # 기계 판독
```

경로를 외우지 말고 `find` 로 잡아라 - 프로필 디렉터리가 `profiles/<부서>/`
를 한 번 더 품는 경우가 있다(실측). 경로를 박아 두면 그 구조가 바뀔 때
"스킬이 없다" 로 읽힌다.

`/app/repo` 가 저장소 전체다(**읽기 전용** - 진단용). 네가 고쳐도 되는 코드는
`/app/departments/04-quant-backtest` 쪽이다. 다른 본부 코드는 보기만 하고,
문제를 찾으면 카드에 적어 그 본부가 알게 한다 - 말없이 고치면 그 본부는
자기 코드가 바뀐 줄 모른다.

## 무엇을 찾아 주나

| 종류 | 뜻 | 신호 강도 |
|---|---|---|
| `key_mismatch` | 넣는 키와 읽는 키가 다르다 | **높다** - 100% 폐기가 여기서 난다 |
| `bounded_digit_regex` | `\d{1,N}` 이 수치를 잘라 읽는다 | **높다** |
| `unselected_columns` | DB 에 있는데 어떤 SELECT 에도 없다 | 중간 - 안 쓰는 열일 수도 |
| `order_assumption` | 정렬 없이 `[-1]` 을 최신으로 쓴다 | 중간 |
| `silent_except` | 예외를 삼키고 사유를 안 남긴다 | 낮다 - 의도한 것도 많다 |

2026-08-12 기준 이 저장소는 340건이 나온다. **전부 결함이 아니다** -
`silent_except` 155건 중 대부분은 "못 읽으면 안 적는다" 같은 의도된 처리다.

## 어떻게 좁히나

**증상에서 출발해 역방향으로 본다.** 340건을 다 볼 일이 아니다.

1. 지금 막힌 값이 무엇인지 정한다 (`amihud` 가 None, `summary` 가 안 온다)
2. 그 값이 지나는 경로를 적는다 (DB 열 → SELECT → API → 클라이언트 → readout)
3. 스캔 결과에서 **그 경로에 있는 것만** 본다
4. 실제로 불러서 확인한다 - 정적 스캔은 후보이지 판정이 아니다

```python
r = get_json(".../bars/005380?limit=3")
print(sorted(r[0]))       # 키 목록을 눈으로 본다
```

## "없다" 를 판정으로 올리기 전에 (2026-08-12 실측 - 이걸로 카드가 죽었다)

한 에이전트가 이렇게 적고 `BLOCKED` 를 냈다:

```
/app/departments/01-research/collectors/source_registry.py: ABSENT
File search under /app: 0 results
→ BLOCKED / NOT_RUNNABLE
"인프라 담당자가 저장소를 복원해야 한다"
```

**파일은 있었다.** `/app/repo/departments/01-research/collectors/source_registry.py`,
54,905바이트. 저장소가 `/app` 이 아니라 `/app/repo` 에 붙어 있었을 뿐이다.
에이전트는 155초를 쓰고, 리스크 게이트가 그 판정을 받아 `NOT_RUNNABLE` 을 냈고,
없는 장애에 대한 조치 요구까지 원장에 남았다.

**한 경로에서 못 찾은 것은 "없다" 가 아니다.** 없다고 쓰기 전에:

```bash
echo "$QUANT_REPO"   # 저장소 루트(읽기 전용). `/app` 이 아니다
echo "$QUANT_WORKSPACE"  # 네가 고쳐도 되는 코드
find / -name "<파일명>" -not -path "*/node_modules/*" 2>/dev/null | head
mount | grep -E "/app|/opt/data"     # 무엇이 어디에 붙어 있나
```

찾아보고도 없으면 그때 없다고 적어라 - **그 구분이 카드의 값이다.** 있는 것을
없다고 하면 다음 사람이 이미 있는 것을 다시 만든다.

## 확인할 때 걸리는 함정

**컨테이너는 이미지에 구운 옛 코드를 쓴다.** 코드를 고쳤는데 안 바뀌면
재빌드를 안 한 것이다. 2026-08-12 에 이걸로 두 번 시간을 태웠다.

**모양을 하나로 가정하지 마라.** 같은 필드가 여러 모양으로 저장돼 있는 일이
실제로 있다 - `partitions` 가 목록·`{키:메타}`·`{count,keys}` 세 가지였고,
`required_data_products` 가 목록과 dict 두 가지였다. 한 모양만 가정한 코드가
`KeyError: 0` 으로 조회면 전체를 죽였다.

## 고친 뒤에 하는 것

**재발하면 실패하는 검사를 남긴다.** 고치기만 하면 다음에 또 난다.

검사가 자기 사고를 실제로 잡는지 확인한다 - 사고 문장 원문을 픽스처로 넣어라.
"검사를 만들었다" 와 "그 검사가 그 사고를 잡는다" 는 다르다.

## 하지 않을 것

**추측으로 채우지 않는다.** 필드가 없으면 없는 것이고, 기본값을 만들어 넣으면
"없다" 는 사실이 사라진다. 못 구한 것과 0 은 다르다.

**한 번에 다 고치지 않는다.** 배관 결함은 얽혀 있어 하나 고치면 다음이
드러난다. 고칠 때마다 실제로 돌려 확인하고 다음으로 간다 - 다섯 개를
한꺼번에 바꾸면 무엇이 효과가 있었는지 모른다.

**증상을 원인으로 착각하지 않는다.** "지표가 부족하다" 는 출발점이다.
새로 만들기 전에 **이미 있는 것이 도달하고 있는지** 먼저 본다.
