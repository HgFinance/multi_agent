# 데이터셋 공학 — 네가 찾고, 네가 만들고, 막히면 네가 뚫는다

## 언제 쓰나

- "이 데이터로 실험하고 싶은데 조회가 안 된다"
- "데이터셋이 없다" 를 카드에 적으려 할 때 — **적기 전에 돌린다**
- 기획안이 요구한 원천이 매니페스트에 없을 때
- 새 원천 표가 생겼는데 실험에서 못 쓸 때

## 먼저: 무엇이 있는지 본다

```bash
SKILLDIR=$(find /opt/data -type d -name dataset-engineering | head -1)
quant-py "$SKILLDIR/scripts/probe_dataset.py" --list
```

```
데이터셋                                덮는 원천                    종목          행수
krx-basket-daily/v3                  market_bars               3,924   7,257,952
krx-microstructure-daily/v1-20260812 microstructure_features  유니버스없음    148,931
```

**`유니버스없음` 은 `0종목` 이 아니다.** 유니버스가 안 걸렸다는 뜻이고,
횡단면 순위(상위 N 매수)를 매길 모집단이 없다는 뜻이다. 행은 멀쩡히 있다.

## 못 쓰겠으면 — 층별로 열어 본다

```bash
quant-py "$SKILLDIR/scripts/probe_dataset.py" <이름>/<버전> --against krx-basket-daily/v3
```

여덟 층을 실제로 열어 본다. **읽은 척하지 않는다** — 파일을 진짜 열고 해시를
다시 계산한다.

```
1 명세 조회        5 load_dataset
2 매니페스트·파티션  6 Market 구성        ← 갈림길
3 파티션 파일      7 식별자 대조
4 읽기·해시        8 유니버스 연결
```

### 왜 층을 나누나 (2026-08-12 실측)

마이크로구조 실험이 이 예외로 죽었다:

```
BadGzipFile: Not a gzipped file (b'PA')
```

메시지만 보면 **파일이 깨진 것**이다. 실제로는 파일이 완벽했고 148,931행이
정상이었다(`PA` 는 Parquet 매직 `PAR1` 의 앞 두 글자다 — gzip 리더로 열어서
난 소리다). 층별로 열어 보니 진짜 그림은 이랬다:

```
1~5 전부 OK   →  6 Market 구성  **KeyError: 'open'**
```

**데이터는 문제가 없었다. 실행면에 "피처 데이터셋" 이라는 자리가 없었다.**

한 층의 예외를 그 층의 문제로 읽으면 엉뚱한 것을 고친다. 그날 나온 오진이
"파일 재생성", "수집기 점검", "인프라 담당자 호출" 이었다. 셋 다 틀렸다.

## 층별로 무엇을 뜻하나 — 그리고 네가 무엇을 하나

| 막힌 층 | 뜻 | 네가 할 것 |
|---|---|---|
| 1 명세 | 등록부에 없다 | `dataset_spec.SPECS` 에 `DatasetSpec` 을 등재한다(아래) |
| 2 매니페스트 | 안 만들었다 | 빌드한다(아래) |
| 3 파일 | 원장엔 있는데 파일이 없다 | 재빌드. 마운트가 붙었는지도 본다 |
| 4 해시 | 파일이 바뀌었다 | **덮어쓰지 말고 새 버전**을 만든다 |
| 5 load | 로더가 못 읽는다 | 명세의 리더·열 선언을 본다 |
| 6 Market | **가격이 없는 데이터셋이다** | 실행면을 넓힌다(아래) |
| 7 식별자 | 종목 키가 안 맞는다 | 사상표를 만든다. 지어내지 않는다 |
| 8 유니버스 | 모집단이 없다 | 유니버스 버전을 걸거나 가격 쪽 유니버스를 쓴다 |

## 데이터셋에는 두 종류가 있다

이 구분을 놓치면 6층에서 계속 막힌다.

| | 가격 데이터셋 | 피처 데이터셋 |
|---|---|---|
| 예 | `krx-basket-daily` | `krx-microstructure-daily` |
| 열 | open/high/low/close/volume | spread_bps, order_flow_imbalance … |
| 쓰임 | **체결·수익률** | **신호** |
| 빌더 | `pit_dataset.py --build` | `spec_dataset_builder.py --build` |
| 로더 | gzip/jsonl | 명세 리더(Parquet) |

`Market` 은 **가격 시계열**이다. 피처 데이터셋을 `Market.from_rows` 에 넣으면
`KeyError: 'open'` 이 난다. 그건 결함이 아니라 **가격이 없는 게 사실**이라는
뜻이다. 피처로 실험하려면 **둘 다** 필요하다 — 체결용 가격 + 신호용 피처.

## 새 데이터셋을 만든다

### ① 가격 계열이면 (기존 경로)

```bash
quant-py pipeline/pit_dataset.py --build --name <이름> --version <버전> \
         --from <YYYY-MM-DD> --to <YYYY-MM-DD>
```

### ② 그 밖의 원천이면 — 명세를 먼저 쓴다

`pipeline/dataset_spec.py` 에 `DatasetSpec` 을 하나 더 만든다. 명세가 소유하는
것: **뽑는 SQL·열·키·정렬·파티션 입자·해시 재료**. 이게 있어야 리더와 해시가
그 데이터셋 모양을 따라간다.

```python
MY_DATASET = DatasetSpec(
    name="krx-something-daily", version="v1",
    columns=(...), key_columns=("instrument_id", "trade_date"),
    partition_column="trade_date", partition_grain="day",   # day | month
    fetch_sql="""select ... where observed_at < %(end)s ...""",
    source_versions={"<원천표>": "<버전>"},
)
SPECS[f"{MY_DATASET.name}/{MY_DATASET.version}"] = MY_DATASET
```

**PIT 를 SQL 에서 지킨다.** `observed_at` 기준으로 자른다 — 나중에 필터로
막겠다고 미루면 그 순간부터 누수는 조용해진다.

```bash
quant-py pipeline/spec_dataset_builder.py --build \
         --name krx-something-daily --version v1 \
         --from 2026-01-01 --to 2026-08-12 --stamp
```

`--stamp` 는 버전에 날짜를 박는다(`v1` → `v1-20260812`). 같은 명세의 다른
스냅샷이라는 뜻이고, 조회는 `spec_for` 가 스탬프를 벗겨 찾는다.

### 버전은 덮지 않는다

v2 가 있으면 v3 를 만든다. 같은 경로에 덮으면 매니페스트 해시와 파일이
어긋나고, 그건 재현성이 깨진 것이다. 해시 가드가 실제로 그걸 잡은 적이 있다.

### 만든 뒤 반드시

```bash
quant-py "$SKILLDIR/scripts/probe_dataset.py" <이름>/<새버전> --against krx-basket-daily/v3
```

**등재됐다 ≠ 실험에 들어간다.** 매니페스트만 보고 "사상됐다" 고 보고했다가
로드에서 죽은 일이 있다. 8층까지 통과해야 들어간 것이다.

## 6층에서 막혔다면 — 실행면을 네가 넓힌다

여기가 이 스킬의 핵심이다. **"기능이 없다" 는 카드를 닫을 사유가 아니다.**

지금 실행면은 데이터셋을 **하나만** 받는다.

```python
register_and_run(name, version, ...)          # 가격 하나
Market.from_rows(rows)                        # open/close 를 요구
PITView.closes / volatility / adv / sma …     # 전부 가격 파생
```

피처를 쓰려면 이런 것이 필요하다 — **설계는 네가 한다.** 아래는 갖춰야 할
성질이지 정답이 아니다.

- 가격 데이터셋과 피처 데이터셋을 **함께** 받는 길
  (`required_data_products` 에 이미 여러 개를 적을 수 있다)
- 피처를 종목·날짜로 가격에 잇기 — 7층에서 교집합을 확인하고 붙인다
- `PITView` 에 **기준일 이하만** 주는 피처 접근자.
  가격과 같은 규율이다. 여기서 PIT 가 깨지면 결과 전체가 미래 정보다
- 피처가 없는 종목은 **결과에서 뺀다.** 0 으로 채우지 않는다 —
  스프레드 0 은 "가장 유동적" 이라는 뜻이 되어 순위를 뒤집는다
- 그 피처를 읽는 템플릿 하나(`strategy_templates.TEMPLATES`)

### 고치기 전에 카드에 적는다

러너를 고쳐도 된다(`experiment-factory` §4). 안전한 이유는 구조에 있다:

```
code_version() = RUNNER_VERSION + sha256(파일)
input_hash     = sha256({dataset, config, code, seed, cost})
```

코드가 바뀌면 **새 실험**이 되지 옛 실험이 오염되지 않는다. 다만 순서가 있다:

1. 무엇을 왜 바꾸는지 카드에 적는다 (사전등록이 먼저다)
2. 자체 점검을 **같이** 낸다 — 특히 PIT 검사와 "안 켜면 이전과 동일" 검사
3. 돌린다
4. 결과가 나쁘면 그것도 결과다. 코드를 되돌려 좋은 쪽을 고르지 않는다

**"안 켜면 이전과 동일" 검사를 꼭 넣어라.** 새 기능이 기존 실험 결과를
바꾸면 사전등록이 무너진다. 오늘 위험관리 손잡이를 넣을 때 이 검사가
그것을 지켰다.

## 지금 열려 있는 것 (2026-08-12)

```
krx-microstructure-daily/v1-20260812   148,931행 · 59일 · 2,558종목
  spread_bps  depth_imbalance  order_flow_imbalance
  trade_intensity  realized_volatility  quality_status
  → 1~5층 통과, 6층 막힘. 식별자는 일봉 3,924종목의 완전 부분집합
```

이 피처들은 지금 아무 실험도 못 쓰고 있다. 반면 `illiquidity_premium`
템플릿은 **거래대금을 비유동성의 대리변수로** 쓰고 있다 — `spread_bps` 는
그 직접 측정값이다. 대리변수를 직접 측정으로 바꾸는 것은 그 자체가 검정할
만한 가설이다.

기간이 59일뿐이라 walk-forward 창이 몇 개 나오는지 먼저 세라
(`experiment-factory` 의 창 산수). **창이 안 나오면 판정이 안 선다** —
그때는 실험을 접는 게 아니라 수집 기간이 쌓일 때까지 다른 것을 하고,
그 사실을 카드에 적는다.

## 두 번째 부류 — 배관은 멀쩡한데 **값이 거짓말하는** 결함

앞의 8층은 "값이 도달하나" 를 본다. 도달해도 틀릴 수 있다. 이쪽이 훨씬
찾기 어렵다 — 예외가 안 나고, 해시도 맞고, 검사도 통과한다. **결과만 이상하다.**

### 2026-08-12 실측 — 어떻게 새는가

`low_volatility` 가 10년 초과 **+855.92%p**, DSR 0.9743, 관문 6/9 통과.
역대 가장 가까웠다. 그런데 알파가 아니었다.

```
상위 3종목 = 실현손익의 63%
1위 종목의 한 체결(2022-03-21) = 34%
   그날 종가:  699 → 7,000   ×10.0143   거래량 0
```

경로가 이렇다:

```
거래정지일은 거래량 0 인데 종가가 이월된다
  → 수익률 0 으로 계산되어 변동성이 깎인다
  → 저변동성 선택이 정지 잦은 종목을 과다 선택한다
     (유니버스 평균 2.4%  vs  선택된 종목 12.9%  = 5.4배)
  → 그 종목들이 정확히 미조정 액면병합 갭을 갖고 있다
  → 백테스트가 그 갭을 수익으로 먹는다
```

**미관측을 0으로 읽은 것이 원인이다.** 이 저장소가 원장 층에서는 열두 번
고친 원칙인데 시세 층에서 깨져 있었다.

### 무엇을 의심하나

| 신호 | 무엇을 뜻하나 |
|---|---|
| `pnl_top1_share` · `pnl_top3_share` 가 크다 | 소수 종목이 성과를 만들었다 |
| 왜도·첨도가 극단(skew 17.9, kurt 380) | 몇 개의 거대한 단일 수익 |
| 승률이 낮은데 총수익이 크다 | 복권형. 저변동성 전략이면 **모순**이다 |
| 정수배 일간 변동(×10.0000, ×0.2000) | 액면분할·병합 미조정 |
| 거래량 0 인 날이 많다 | **관측이 없는 것**이지 무변동이 아니다 |

**전략의 성격과 수익의 모양이 안 맞으면 거기서 멈춰라.** 저변동성이 복권형
수익을 내면 그건 저변동성 전략이 아니다.

### 공장이 알려 준다

병목 인구조사가 매 주기 시세를 직접 세어 개선 카드로 올린다:

```
시세 미관측     166,707봉   일봉 중 거래량 0 이 2.4%
시세 정수배 갭       25건   ×10.0000 (2017-05-28 ~ 2026-07-29)
```

**이 카드가 오면 네가 정한다.** 답은 하나가 아니다:

- 거래량 0 인 날을 수익률·변동성 계산에서 **뺀다**(표본이 짧아지는 것을 감수)
- 그 날을 결측으로 두고 종목을 **결과에서 뺀다**(러너가 이미 쓰는 방식)
- 정수배 갭이 있는 종목을 유니버스에서 제외한다
- 조정계수를 따로 모아 적용한다 — 다만 **소급 조정은 PIT 를 깬다**.
  오늘 받은 수정주가로 2019년을 돌리면 그때 몰랐던 정보가 들어간다

**어느 쪽이든 실험으로 검증해라.** 고르고 나서 같은 계열을 다시 돌리면
그 선택이 옳았는지 숫자가 말한다. 그게 이 공장이 하는 일이다.

### 재수집으로 안 풀리는 것도 있다

이번 건은 수집기가 **이미 수정주가를 요청하고 있었다**(`sujung=Y`).
정수배 갭 25건이 **같은 수집 배치 안**에 있었다 - 증분 수집 문제도 아니다.
벤더 조정이 거래정지 구간을 안 덮은 것이다.

**"다시 받으면 되겠지" 를 확인 없이 하지 마라.** 10년치 재수집은 비싸고,
이 경우엔 같은 값이 온다. 먼저 **한 종목을 골라 원천에서 직접 확인해라.**

## 하지 않을 것

**"조회가 안 된다" 로 카드를 닫지 않는다.** 어느 층에서 막혔는지 없으면
다음 사람이 처음부터 다시 판다. 프로브 출력을 그대로 붙여라.

**예외 메시지를 원인으로 옮겨 적지 않는다.** `BadGzipFile` 은 증상이었고
원인은 명세 조회 실패였다. 층을 세면 그 둘이 갈린다.

**없는 값을 채우지 않는다.** 피처가 없는 날·종목은 빼는 것이지 0이 아니다.
미측정과 0을 섞는 순간 판정이 오염된다.

**유니버스 없이 횡단면 순위를 매기지 않는다.** 모집단이 정의되지 않은
"상위 20종목" 은 생존편향을 그대로 담는다.
